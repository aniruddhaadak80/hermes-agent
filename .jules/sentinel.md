## 2024-05-18 - Prevent Secret Leakage in `shell.exec`
**Vulnerability:** The `shell.exec` method in `tui_gateway/methods_tools.py` executed arbitrary shell commands (`subprocess.run(..., shell=True)`) without sanitizing the environment variables. Because the TUI server process holds API keys and secrets in `os.environ`, these secrets could be leaked to the shell environment of the child process.
**Learning:** Even though `shell.exec` passes through an approval gate, any command that gets approved could inadvertently access or leak secrets if the environment isn't sanitized.
**Prevention:** Always use `build_subprocess_env()` from `tools.environments.local` to sanitize the environment before executing shell commands that shouldn't inherit the parent process's credentials.

## 2024-05-20 - Sanitize subprocess environments for external commands
**Vulnerability:** The codebase occasionally spawns external commands (especially during installations, bootstraps, or plugins execution) using `subprocess.run` with `shell=True` without explicitly defining a sanitized environment (`env=`). Because `os.environ` is inherited by default, this can leak API keys, credentials, and sensitive configurations to third-party tools or arbitrary shell scripts.
**Learning:** `os.environ` contains all API keys required for the agent to run. Any time we use `subprocess.run(..., shell=True)` (or `subprocess.Popen`) to execute user-defined or third-party code without restricting the environment, we expose the entire environment to the child process. The project has a specific utility `build_subprocess_env()` in `tools.environments.local` that scrubs these secrets.
**Prevention:** Always use `build_subprocess_env()` from `tools.environments.local` when spawning subprocesses, especially when executing non-internal or shell-based commands. Ensure `env=build_subprocess_env()` is passed to `subprocess.run`, `subprocess.Popen`, `subprocess.call`, etc., unless it's explicitly designed to inherit everything.
